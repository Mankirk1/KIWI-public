## Improvement backlog

Ranked by expected value. Each entry is **[done]** (with the PR), **[partly done]** or **[open]**.
"Run-2 fixes" means the PR from branch `agentbox/run2-fixes` (2026-10-16).

27. **[done, branch agentbox/night-rails-oracle: locked tests are kept in the task state until it merges] Work from a tests phase is lost when the budget ends right after it.** The budget is checked before each implementation attempt, so a run can stop just after the owner locks the tests; the next run starts the task again from a fresh branch and rewrites them. Idea: keep approved locked tests on the task branch and reuse them when the task resumes, or check the budget before starting a tests phase that can't be followed by an implementation.
28. **[done, branch agentbox/field-notes-run3] Console scripts installed by pip were not on PATH in the sandbox.** The test runner and the coder's `run_command` use a login shell (`bash -lc`), whose `/etc/profile` resets PATH to `/usr/local/bin:/usr/bin:/bin:...` and drops `~/.local/bin`, where `pip install -e .` (a user install: non-root, no venv) puts `mechcalc`. So T5's locked test `subprocess.run(['mechcalc', 'materials'])` cannot pass in the sandbox, although it would on GitHub CI. The coder saw pip's warning "installed in '/home/agent/.local/bin' which is not on PATH". Fix: an `/etc/profile.d` entry in the worker image that puts `$HOME/.local/bin` first in PATH, plus a sandbox test.
29. **[partly done, branch agentbox/speed-and-sentinel] Generation slows to about 6 tok/s in long coder conversations.** See [2026-10-19-speed-and-sentinel.md](2026-10-19-speed-and-sentinel.md): a cache-preserving compaction policy (60% → 40%) gives −24% end to end and −12% in the controlled replay, with generation at about 7.8 tok/s instead of 5.9. A deeper variant was rejected after it made the coder re-read files. Run 3 averaged 6.4 tok/s generation (llama bench: 11.4 at 4k context) because coder contexts grew past 13k tokens, and compaction then discarded the prompt cache (item 26's neighbour). Ideas: clip tool outputs harder, compact earlier but keep the static prefix byte-identical, and test the Q4_K_M/Q4_0 quants (roadmap section 4).
30. **[open] CI timeouts are opaque.** T6's PR #14: the orchestrator waited the full 20 min (`ci.wait_timeout_min`) and reported "CI: timeout", although mechcalc's CI normally finishes in about a minute. Neither the gate nor Sentinel says whether the run was queued, still running or never triggered, and the supervising session can't read the org's checks. Ideas: report the CI run's state and URL at the merge gate, add a Sentinel rule for CI not starting within N min, and give the supervising session read access to the org (item 24).
31. **[done, branch agentbox/night-rails-oracle: `control.night`, `budget.max_wall_hours`, quiet notifications] With `always_ask: [merge]`, a night run does at most one task.** The run waits at its first merge question (`approval_timeout_min: 0`) until the owner answers. That holds until the Windows task's 9-hour limit (`Register-NightlyTask.ps1 -MaxHours 9`) ends it, and the limit can also cut an attempt short, because the 8-hour budget is checked only before attempts. Each merge question also sends an ntfy push at night. Ideas: `on_timeout: skip` with a timeout so the run hands the PR to the owner and moves on to tasks that don't depend on it, or quiet hours for ntfy.
